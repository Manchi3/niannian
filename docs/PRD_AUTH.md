## 项目信息

| 项目 | 内容 |
|------|------|
| 项目名称 | `particle_diary`（粒子日记 / 念念） |
| 文档版本 | v1.0（本轮迭代 PRD，替代方向为「账号体系 + 个人资料 + 长期记忆」） |
| 语言 | 中文 |

### 工程红线（本轮必须遵守）

- **保护文件一行不准动**：粒子系统 7 文件、`EllipseParticles.tsx`、`AmbientBackground`、`RingCursor`、`useAutoHideUI`、`StackView`、`CorridorView`、`GridView`、粒子聊天核心逻辑。
- **保留既有成果**：圈点光标、翻开这一天按钮、3s 自动隐藏、标签页标题「念念 — 每日文案」、黄色四角星 favicon、网格浮字微光、长廊滚轮拖拽。
- 现有业务接口（`/api/chat`、`/api/condense`）行为不破坏，仅新增「从 token 解析 uid、无 token 则 uid=guest」的命名空间层。

## 一、产品目标

1. **建立可信赖的账号体系**：注册/登录/恢复登录态/按账号隔离数据，让每位用户拥有独立且安全的「念念」空间（guest 数据永远留 guest，登录后不合并不互通）。
2. **提供可管理的个人身份**：昵称、头像、密码可随时编辑并即时生效，顶栏、资料层、服务端三者同步一致。
3. **沉淀可掌控的长期记忆**：用户亲手书写、可查看、可长按删除的长期记忆，成为后续对话理解用户的「人格底座」。

## 四、UI 说明（七节）

### 4.1 账号后端与存储布局（服务端）

**数据布局（server/data/）：**

| 路径 | 内容 |
|------|------|
| `server/data/users.json` | 账号索引 `[{id, contact, nickname, passHash, avatar, createdAt}]` |
| `server/data/{uid}/memories.json` | 长期记忆（本轮新功能，走服务端） |
| `server/data/{uid}/days.json` | 聊天/日记（本轮**不落地**，保持本地 IndexedDB） |
| `server/data/{uid}/photos/` | 图片（本轮**不落地**，保持本地 OPFS） |

**接口清单（server 新增，不破坏现有接口）：**

| 方法 | 路径 | 入参 | 返回 |
|------|------|------|------|
| POST | /api/auth/code | {contact} | 开发模式响应含 6 位验证码 + toast + 控制台打印；5 分钟有效 |
| POST | /api/auth/register | {contact, code, nickname?, password?} | {token, user} |
| POST | /api/auth/login | {contact,password} 或 {contact,code} | {token, user} |
| GET | /api/auth/me | Bearer token | {user} |
| PUT | /api/user/profile | {nickname?, avatar?} | 更新后的 user |
| PUT | /api/user/password | {password} | 成功状态 |

- 现有业务接口（/api/chat、/api/condense）一律从 token 解析 uid，无 token 则 uid=guest。
- 密码 SHA-256 加盐存储，不存明文。

**前端登录态：**
- token 存 `localStorage.nn_token`；App 启动 `GET /me` 恢复登录态。
- 本地缓存 key 统一：`const uid = () => currentUser?.id ?? 'guest'; const key = (k) => `nn_${uid()}_${k}``。
- 切换账号/登出后用新 uid 重新拉数据刷新视图。

### 边界决策（本轮已定，直接执行）

**D1. days.json / photos/ 本轮不落地 server。**
只落地 `memories.json`（新功能天然走服务端）；聊天/日记与图片保持浏览器本地（IndexedDB / OPFS），本轮只做 uid 命名空间隔离，不做迁移、不做双写。理由：① 用户明确只做「加鉴权接口」与「加命名空间」两件事，数据迁移/双写风险大且超范围；② 本地 + uid 命名空间已满足账号隔离；③ 跨设备同步日记/图片属未来迭代（旧 PRD P2-1 的延伸）。

**D2. guest 的长期记忆走 server（`server/data/guest/memories.json`，无鉴权读写）。**
理由：① 与「现有业务接口无 token 则 uid=guest」完全一致，服务端统一解析 uid，前端无需维护第二套本地读写逻辑；② guest 数据永远留 guest，登录/注册后不合并不互通。**产品提示（需知悉）**：所有未登录访客共享同一个 guest 记忆空间，匿名用户之间会互相看到 guest 记忆；本轮可接受（guest 空间无敏感 PII、开发阶段），若上线前在意可改为「guest 记忆仅存本地」。

**D3. 头像上传复用 `PUT /user/profile` 的 avatar 字段（base64 data URL，canvas 256px 压缩）。**
不单独建 `POST /api/user/avatar`。理由：① 少一个接口与路由，avatar 本就是 user 对象属性，模型统一；② 256px base64 约 20–60KB，users.json 可承受。接口侧加保护：校验 avatar 为 `data:image/(png|jpeg|webp);base64,...` 且总长 ≤200KB，超限返回 400。
